Session 1 (6 AM – 8 AM)
Fixed Size Chunking

Most basic method.

Split every N characters.

Example:

chunk_size = 500

Document:

1000 Characters

Produces:

Chunk 1 → 500

Chunk 2 → 500

Advantages

Simple
Fast
Easy

Disadvantages

Breaks Context
Breaks Sentences
Character Splitter
from langchain_text_splitters import (
    CharacterTextSplitter
)

splitter = CharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50
)
Recursive Chunking

Most commonly used.

from langchain_text_splitters import (
    RecursiveCharacterTextSplitter
)

Example:

splitter = (
    RecursiveCharacterTextSplitter(
        chunk_size=500,
        chunk_overlap=50
    )
)

Hierarchy:

Paragraph

 ↓

Sentence

 ↓

Word

 ↓

Character

Preserves meaning better.

Recommended Settings
Document Type	Chunk Size	Overlap
FAQs	300	30
Banking Policies	500	50
Insurance Docs	1000	100
Legal Contracts	1500	150

Interview Questions
What is chunking?

Splitting documents into smaller pieces before embedding.

Why is chunking necessary?

Because LLMs and vector databases work better with smaller semantic units.

What is Recursive Chunking?

A chunking strategy that preserves document structure using multiple separators.

What is Semantic Chunking?

Chunking based on meaning instead of fixed size.

Why use overlap?

To preserve context across chunk boundaries.

What is Parent-Child Retrieval?

Store large parent chunks and retrieve through smaller child chunks.

What happens if chunk size is too large?

Retrieval becomes less precise.

What happens if chunk size is too small?

Important context gets lost.

Which chunking strategy is most common?

RecursiveCharacterTextSplitter.

Which chunking strategy is best?

There is no universal best approach. It depends on document type and retrieval performance.
