Day 50 – Corrective RAG (CRAG)

Today you'll learn a very advanced RAG architecture used when retrieval quality is unreliable.

Traditional RAG assumes:

Retriever
   ↓
Relevant Documents
   ↓
LLM

But in real-world systems, retrievers often return:

Irrelevant Documents
Outdated Documents
Partial Information
Wrong Context

This causes hallucinations.

What is Corrective RAG (CRAG)?

CRAG = Corrective Retrieval-Augmented Generation

The system evaluates retrieved documents before generating an answer.

If retrieval quality is poor:

Query

↓

Retrieve

↓

Evaluate Retrieval Quality

↓

Good?
   ├─ Yes → LLM
   └─ No  → Correct Retrieval
            ↓
           LLM

Interview Questions
What is Corrective RAG?

A RAG architecture that evaluates retrieved documents and corrects retrieval failures before generation.

Why do we need CRAG?

Because retrievers may return irrelevant or incomplete information.

What is a Retrieval Evaluator?

A component that measures retrieval quality before generation.

What happens if retrieval quality is low?

The system triggers corrective actions such as re-querying, multi-query retrieval, or web search.

How does CRAG reduce hallucinations?

It prevents poor-quality retrieval results from reaching the LLM.

What corrective techniques are commonly used?
Query Rewriting
Multi Query Retrieval
Hybrid Search
Web Search Fallback
Re-ranking
What is the biggest challenge in CRAG?

Choosing the correct confidence threshold.

How is CRAG different from normal RAG?

CRAG validates and fixes retrieval before answer generation.

Can CRAG work with Hybrid Search?

Yes. Hybrid Search is commonly used as a corrective strategy.
