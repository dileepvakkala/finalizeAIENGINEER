Day 33 – Text Splitters (Chunking for RAG)

Today you'll learn one of the most important topics in RAG systems:

Text Splitters = Chunking

A large PDF cannot be sent directly to an LLM because of context window limitations and retrieval inefficiency.

So we split documents into smaller chunks.

Session 1 (6 AM – 8 AM)
CharacterTextSplitter

Basic splitter.

from langchain_text_splitters import (
    CharacterTextSplitter
)

Example:

splitter = CharacterTextSplitter(
    separator="\n",
    chunk_size=100,
    chunk_overlap=0
)

Split:

chunks = splitter.split_text(text)

Output:

Chunk 1
Chunk 2
Chunk 3
Understanding Chunk Size
chunk_size=500

Means:

Maximum 500 characters per chunk

Example:

chunk_size=1000

Produces larger chunks.

Understanding Chunk Overlap
chunk_overlap=100

Example

Original Text:

A B C D E F G H I J

Chunk 1:

A B C D E

Chunk 2:

D E F G H

Notice:

D E

appears in both chunks.

Why?

To avoid losing context at chunk boundaries.

Session 2 (11 AM – 1 PM)
RecursiveCharacterTextSplitter

Most commonly used splitter.

Used in:

Enterprise RAG
Banking Chatbots
Insurance Assistants
Knowledge Bases

Import:

from langchain_text_splitters import (
    RecursiveCharacterTextSplitter
)

Example:

splitter = (
    RecursiveCharacterTextSplitter(
        chunk_size=500,
        chunk_overlap=50
    )
)

Split Documents:

chunks = (
    splitter.split_documents(
        documents
    )
)

Why Recursive?

It tries multiple separators.

Example:

Paragraph
 ↓

Sentence
 ↓

Word
 ↓

Character

This preserves meaning better.

Recommended Settings

Small Documents:

chunk_size=300
chunk_overlap=30

Medium Documents:

chunk_size=500
chunk_overlap=50

Large Banking PDFs:

chunk_size=1000
chunk_overlap=100

Token-Based Splitters

LLMs think in tokens, not characters.

Example:

Hello World

Tokens:

Hello
World

Token Splitter:

from langchain_text_splitters import (
    TokenTextSplitter
)

Example:

splitter = TokenTextSplitter(
    chunk_size=200,
    chunk_overlap=20
)

Used when:

Token Control Required
Semantic Chunking

Advanced Production Technique.

Instead of fixed size:

500 chars
500 chars
500 chars

Split based on meaning.

Example:

Loan Section

becomes:

One Chunk
Eligibility Section

Another Chunk

Benefits:

Better Retrieval
Better Accuracy

Full Example
from langchain_community.document_loaders import (
    PyPDFLoader
)

from langchain_text_splitters import (
    RecursiveCharacterTextSplitter
)

loader = PyPDFLoader(
    "loan_policy.pdf"
)

documents = loader.load()

splitter = (
    RecursiveCharacterTextSplitter(
        chunk_size=500,
        chunk_overlap=50
    )
)

chunks = (
    splitter.split_documents(
        documents
    )
)

print(len(chunks))

Interview Questions
What is chunking?

Splitting large documents into smaller pieces for retrieval and embeddings.

Why is chunking required?

Improves retrieval quality and handles context limitations.

What is chunk size?

Maximum content allowed in one chunk.

What is chunk overlap?

Shared content between adjacent chunks.

Why is overlap important?

Preserves context across chunk boundaries.

What is RecursiveCharacterTextSplitter?

A splitter that recursively splits using paragraphs, sentences, words, and characters.

Why is it preferred?

Maintains semantic meaning better than simple splitting.

What happens if chunk size is too large?

Poor retrieval and unnecessary context.

What happens if chunk size is too small?

Loss of context and fragmented information.

What is semantic chunking?

Chunking based on meaning instead of fixed size.
